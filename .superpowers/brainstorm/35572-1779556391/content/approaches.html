Three Approaches to the Memory Layer

All three use two vaults + auto-export on EOD. They differ in how the bridge works and how much the Tony Stocks agent does.

A

File Drop Bridge

Bot writes a clean JSON export to bridge/tony-stocks/daily-export.json after EOD. Tony Stocks agent reads that file and manually (or via a separate Claude session) updates the Command Center vault.

✓ Simplest to build
✓ No dependencies
⚠ Tony agent update is manual
⚠ Vault 2 doesn't auto-update
B

Full Auto Pipeline RECOMMENDED

Bot writes Vault 1 notes + bridge export after EOD. A Python script in the bot then calls the Command Center's Tony Stocks agent (via Claude API) to enrich and write directly to Vault 2. Fully automated end-to-end.

✓ Fully hands-off
✓ Vault 2 always current
✓ Tony adds real insight
✗ Needs Claude API key + cost per run
⚠ More moving parts
C

Markdown-First, Agent-Later

Bot writes rich Vault 1 markdown (daily notes, ticker pages, signal history) + a clean bridge file. No Tony agent call yet — you open the bridge file in your Command Center session and run Tony manually when you want deeper analysis. Build the agent automation later once the vault format is proven.

✓ Vault 1 gets built now
✓ Low risk, easy to extend
✓ Proves the format before automating
⚠ Tony agent step stays manual for now
My take
Start with C, build toward B. Get the vault format right with real data first, then add the API automation once you know what Tony should be saying. Trying to automate Tony before the vault structure is proven tends to produce garbage at speed.
