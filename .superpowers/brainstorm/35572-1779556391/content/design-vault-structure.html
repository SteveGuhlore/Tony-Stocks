Design — Section 1: Vault 1 Folder Structure

Lives at vault/ inside TradingBotAgentProject. Obsidian-compatible markdown throughout.

Folder Tree
vault/
├── index.md
├── daily/
│ ├── 2026-05-22.md
│ └── 2026-05-23.md
├── signals/
│ ├── GTLB.md
│ ├── ZETA.md
│ └── ...
├── outcomes/
│ ├── 2026-05-22-outcomes.md
│ └── ...
├── strategy/
│ ├── v1.md
│ └── proposals.md
└── memory/
└── agent-context.md
vault/index.md
Root overview — active positions, current strategy version, links to recent daily notes. The entry point when you open the vault in Obsidian.
vault/daily/YYYY-MM-DD.md
One note per trading day. Scan summary, top signals with conviction tier, EOD self-review, strategy notes, links to ticker pages. Auto-written at EOD.
vault/signals/TICKER.md
One note per ticker that has ever appeared. Days active, setup type, score history, current status, outcome if closed. Grows over time — permanent signal memory.
vault/outcomes/YYYY-MM-DD-outcomes.md
Target hits, stop hits, open positions, P/L summary. Written when outcomes are recorded. The performance ledger.
vault/strategy/
v1.md, v1.1.md etc — each strategy version as its own note. proposals.md tracks rule suggestions and their approval status.
vault/memory/agent-context.md
A single file Claude can read to get full project context at the start of a session — a curated summary of vault state, not a raw dump.
Seeding: On first setup, a one-time script reads the existing SQLite database and backfills daily/, signals/, and outcomes/ from all stored records — so the vault isn't empty on day one.
Git: vault/ is tracked in git so history is preserved. Signal pages and daily notes are small markdown files — no bloat.
